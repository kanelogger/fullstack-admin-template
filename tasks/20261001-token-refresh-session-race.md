# Token 刷新与 Session 切换竞态

- 状态：阻塞
- 来源：用户复评指出退出或切换账号时，旧 Token 刷新结果仍可能覆盖新 Session。
- 目标：保证只由发起刷新时仍有效的会话接收刷新结果；不让旧刷新错误登出新会话或清除新刷新任务。
- 验收：
  - 登录/退出改变 Session 版本；刷新请求带上预期版本与 refresh token。
  - 响应写回前验证版本、持久化 refresh token 和活跃 Session 标记；Access Token Cookie 缺失时允许正常刷新，存在时需与预期 refresh token 相符。
  - 重放原请求前再次验证刷新结果仍属于当前 Session。
  - 并发刷新按 Session 版本和 refresh token 合并；旧任务不会覆盖或清除新任务。
  - 前端类型检查、生产构建与本地登录页检查通过。
- 下一步：本地后端和授权测试账号准备就绪后，验证未登录拒绝、正常登录/动态路由、刷新失败，以及刷新期间登出和切换账号。
- 阻塞：本地后端 `.env` 与依赖不存在、3000 端口未监听；不能验证真实认证与慢刷新竞态。数据库 Seed/Schema 执行需按仓库安全规则另行授权。

# Git Rules

- 开始前检查 `git status`，已有或并发修改视为用户资产，不覆盖、不混入本次改动。
- 每一行改动都应能追溯到当前需求；不打包无关修改。
- 不擅自推送、发布、变基、改写历史或执行破坏性清理。
- 验证完成后报告变更清单和验证结果；不自动创建提交，是否提交、何时提交由用户决定。
- 用户要求提交或推送时，统一通过 `git-commit-push` Skill 执行：暂存边界、敏感信息审查、提交消息生成和推送核验以 Skill 流程为准；本文件只补充 Skill 未覆盖的约束，冲突时以 Skill 为准。
- 用户要求提交时，一个逻辑变更形成一个提交；实现、测试和直接相关文档在同一个提交中。
- 并行实现只是迁移手段：替换验证通过后必须删除旧路径，旧实现不得与新实现永久共存。
- 只读任务不创建空提交；未通过的检查必须明确报告。
